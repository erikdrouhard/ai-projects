Example 4: Declarative Forms

Expose HTML forms as AI-callable tools using WebMCP attributes

Key Concept: Declarative vs Imperative

WebMCP supports two approaches. The Imperative API (Examples 1-3) uses JavaScript to register tools with navigator.modelContext.registerTool(). The Declarative API adds attributes directly to HTML form elements, letting the browser automatically expose them as tools. This means zero JavaScript required for basic form actions.

Restaurant Reservation (Declarative)

toolname="make_reservation" tooldescription="Book a table at Le Petit Bistro"

Reservation Confirmed!

Key Concept: toolautosubmit

When a form has the toolautosubmit attribute, the browser auto-submits it when an agent fills in all fields. Without this attribute, the form requires a human gesture (click/tap) to submit — enforcing the "human-in-the-loop" principle. The reservation form above omits toolautosubmit, meaning a user must manually confirm.

Quick Feedback (Declarative + Auto-submit)

toolname="submit_feedback" toolautosubmit (auto-submits when agent fills fields)

Thank you for your feedback!

Declarative vs Imperative: Side by Side

Declarative (HTML attributes)

<form
  toolname="make_reservation"
  tooldescription="Book a table"
>
  <input name="guest_name"
    type="text" required>
  <input name="date"
    type="date" required>
  <button type="submit">
    Book
  </button>
</form>

Imperative (JavaScript)

navigator.modelContext
  .registerTool({
  name: "make_reservation",
  description: "Book a table",
  inputSchema: {
    type: "object",
    properties: {
      guest_name: {
        type: "string"
      },
      date: {
        type: "string",
        format: "date"
      }
    },
    required: [
      "guest_name", "date"
    ]
  },
  async execute(args) {
    // handle booking...
  }
});

Key Concept: When to Use Which?

Use declarative for standard form-based actions (signup, search, booking) — it requires no JS and works with existing forms. Use imperative for complex dynamic interactions (filtering, multi-step workflows, state queries) where you need full programmatic control. Many real apps will use both together.
